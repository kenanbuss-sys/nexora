# Customer Implementation Method

The platform is implemented through configuration and integrations before custom development.

## 1 Discovery
Map legal entities, sites, products, channels, processes, users, existing systems, paper/Excel/manual steps, volumes, controls and pain points.

## 2 AS-IS
Document current process, source-of-truth system, handoffs, documents, approvals, duplicate entry and failure points.

## 3 TO-BE
Design target process using existing platform capabilities and identify measurable outcomes.

## 4 Capability mapping
For each requirement classify: existing capability/configuration, integration, industry-pack template, or truly missing capability.

## 5 Source-of-truth & migration
Define what remains external, what migrates, sync direction, cutover and reconciliation.

## 6 Configuration
Organization, roles, branding, terminology, fields, forms, workflows, rules, documents, dashboards, devices, integrations.

## 7 Custom extension only when needed
New reusable capability goes into core/extension architecture after product review. Customer-specific one-off code is last resort and must remain isolated through approved extension points.

## 8 Pilot
One bounded site/process with real acceptance criteria.

## 9 Rollout
Phased deployment, training, data reconciliation, support and rollback plan.

## 10 Stabilization
Measure adoption, errors, process cycle time, integration health and business outcomes.
